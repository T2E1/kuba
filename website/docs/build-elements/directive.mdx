# directive

```js
import {
  adopted,
  attributeChanged,
  connected,
  define,
  disconnected,
  execute,
  formAssociated,
  formDisabled,
  formReset,
  formStateRestore,
} from '@t2e1/kuba/directive'
```

Decorators over the native custom element lifecycle. Each one wraps a callback
rather than replacing it, so several can hook the same callback and they chain.
See [Lifecycle](/build-elements/lifecycle) for how they fit together.

## `define(name, options?)`

Class decorator. Registers the class in the custom element registry, skipping
registration when `name` already exists — so a module evaluated twice doesn't
throw.

```js
@define('my-counter')
class Counter extends HTMLElement {}
```

| Parameter | Type | Description |
|---|---|---|
| `name` | `string` | Tag name. Must contain a hyphen, per the platform. |
| `options` | `ElementDefinitionOptions` | Passed through to `customElements.define`, e.g. `\{ extends: 'button' \}`. |

## `attributeChanged(attribute, ...filters)`

Accessor decorator. Adds `attribute` to `observedAttributes` and syncs the
decorated property from it on every `attributeChangedCallback`, passing the raw
string through `filters` in order first.

```js
@attributeChanged('count')
set count(value) { this.#count = Number(value) }

@attributeChanged('hidden', booleanAttribute)
set hidden(value) { this.#hidden = value }
```

The direction is attribute → property only. Setting the property does **not**
write the attribute back.

### Filters

Importable from `@t2e1/kuba/directive/attributeChanged`:

| Filter | Turns the raw value into |
|---|---|
| `booleanAttribute` | `true` when the attribute is present, `false` when removed |
| `resizing` | a CSS length — numeric px/% values pass through, keywords are normalized |

## Lifecycle hooks

Method decorators. Each runs the decorated method **after** the corresponding
native callback, receiving the same arguments.

| Decorator | Runs after |
|---|---|
| `connected` | `connectedCallback` |
| `disconnected` | `disconnectedCallback` |
| `adopted` | `adoptedCallback` |
| `formAssociated` | `formAssociatedCallback` |
| `formDisabled` | `formDisabledCallback` |
| `formReset` | `formResetCallback` |
| `formStateRestore` | `formStateRestoreCallback` |

```js
@connected
[slottable]() {
  this.setAttribute('slot', 'helper')
  return this
}
```

Symbol-keyed methods are the convention here — they keep the hook off the
public surface of the element. Each package defines its own in an
`interface.js`.

## `execute(method)`

The builder behind every hook above. Use it to write your own:

```js
const ready = (target, method) =>
  execute(method).on(target).after('connectedCallback')
```

| Step | Argument | Description |
|---|---|---|
| `execute(method)` | `string \| symbol` | The method to invoke on the instance. |
| `.on(target)` | prototype | Where to install the wrapper. |
| `.after(event)` | `string` | Name of the callback to wrap. |

It proxies the existing callback instead of overwriting it, which is what makes
hooks composable.
