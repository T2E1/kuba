# Redirect

`<kb-redirect>` navigates the browser via `history.pushState` when its
`go()` method runs, without triggering a page reload. It renders nothing
and owns no visible interaction of its own — it's a headless Echo
subscriber, meant to be wired (via `on`/`<kb-on>`) to another element's
event, most commonly a button's `clicked` event. See
`Guides/Declarative navigation`.

## When to use

- The outcome of an interaction (a button click, a form submission) is a
  **new location** — wire the triggering element's event to `go()` via
  `on`/`<kb-on>` instead of writing a manual `history.pushState` call in
  page code.
- Navigating to a **named, router-registered route** (via `route`) or to
  a **path with dynamic segments** (via `href` placeholders interpolated
  from the triggering event's payload).

## When not to use

- **The interaction's outcome is not a navigation** — e.g. a button that
  submits a form or dispatches a local `clicked` event with no location
  change. Keep `<kb-button>`'s `clicked` event unwired to `<kb-redirect>`
  in that case; putting navigation logic in the button itself would
  couple it to a destination it shouldn't know about.
- **A full-page navigation or an external URL** — use a plain `<a>`;
  `<kb-redirect>` only ever calls `history.pushState`, which never leaves
  the current page or triggers a real browser navigation.

## Composition

- **Can contain**: nothing — `<kb-redirect>` has no slot and renders no
  shadow DOM.
- **Can be a child of**: anything — `kb-redirect` has no parent
  requirement. It's commonly placed as a sibling of the element whose
  event it subscribes to via `on` (e.g. right after a `<kb-button>`), not
  nested inside it.

## `href` vs `route`

- `href` — a direct URL: an absolute URL, an absolute path, or a
  fragment/query starting with `#`/`?`. May contain `{path.to.value}`
  placeholders (e.g. `href="/user/{id}"`), interpolated against the
  `params` passed to `go()`.
- `route` — a router-registered route name, resolved via `urlFor`.
  Takes precedence over `href` when both are set — don't set both
  expecting `href` to act as a fallback; only `route` is ever used in
  that case.

## States and accessibility

- `<kb-redirect>` is headless and invisible — it has no rendered state or
  accessibility surface of its own. The accessible name and role that
  matter belong to whatever element triggers it (e.g. the button wired to
  `go()` via `on`).

## Do's and don'ts

| Do | Don't |
|---|---|
| Wire a triggering element's event to `go()` via `on`/`<kb-on>` | Call `history.pushState` manually in page code when `<kb-redirect>` already covers it |
| Use `route` for router-registered destinations | Set both `href` and `route` expecting a fallback — `route` always wins when set |
| Use `href` placeholders for dynamic segments from the event payload | Hardcode a dynamic id into `href` instead of interpolating it via `params` |
