# Footer

A footer is the closing bar of a page: a strip that fills the width it's
given and pins one group of content to the start of a centered row
(`leading`) and another to its end (`trailing`). It's a page-level
landmark, not a generic container — it has no attributes, dispatches no
events, and carries no default (unnamed) slot, so anything that isn't
assigned to `leading` or `trailing` is dropped.

## When to use

- **Closing a page** with the legal/secondary content that belongs at the
  very bottom — copyright line, privacy and terms links, locale switcher.
- **Pairing with `<kb-header>`** so a page opens and closes with the same
  centered 1024px column and the same 72px bar height.

## When not to use

- **The top bar of the page** — use `<kb-header>`, which is the same
  centered-row primitive but lays its `leading`/`trailing` regions out as
  flex rows (see Composition below) and is the matching landmark for that
  end of the page.
- **A footer inside a card, dialog, or section** — `kb-footer` renders a
  native `<footer>` and exposes a `contentinfo` landmark, which belongs to
  the page, not to a component; use a `<kb-stack>` (or plain markup) for
  the action row at the bottom of a contained surface.
- **Grouping arbitrary content into two columns** — use `<kb-stack>` or
  a `<kb-card direction="row">`; `kb-footer` fixes the height, the max
  width, and the viewport-wide background strip.

## Composition

- **Can contain**: anything, as long as it carries `slot="leading"` or
  `slot="trailing"` — `kb-footer` renders only those two named slots and
  no default slot (see `component.js`), so unslotted children never appear.
  Typical content is `<kb-text>` for the copyright line and `<kb-button
  variant="link">` or `<a>` for secondary links.
- **Can be a child of**: anything — the bar fills 100% of whatever width
  it's given and only caps its inner row at `--footer-size-max-width`, so
  it adapts to a narrower container instead of overflowing it. Semantically
  it still belongs at the page root: it's the page's `contentinfo`
  landmark, not a section-level one.

Each slot's wrapper (`<leading>` / `<trailing>`) is a plain unstyled
element — unlike `<kb-header>`, it doesn't lay its children out as a flex
row. Two elements slotted into the same region flow inline with no gap, so
wrap them in a `<kb-stack direction="row">` when you need spacing or
alignment between them.

## Content

`leading` has built-in fallback content — a copyright line — that shows
whenever nothing is slotted into it. Treat it as a placeholder, not a
default to ship: it hardcodes a year, a company name, and Portuguese
wording, so any real page should slot its own line. `trailing` has no
fallback and stays empty until filled.

Keep both sides short — the bar is a fixed 72px tall and doesn't grow, so
content that wraps will overflow it rather than push it taller.

## Styling

Every visual decision is exposed as a `--footer-*` CSS custom property with
a default that aliases a global token from `packages/pixel/tokens/` (or, for
the two dimensions, a plain value). Because custom properties inherit
through the shadow boundary, you re-style a footer by setting these on the
element (or any ancestor) — never by reaching into its shadow DOM. Override
a token, not the internals.

| Custom property | Default | Controls |
|---|---|---|
| `--footer-size-height` | `72px` | Height of the bar, on both the host and the inner centered row. |
| `--footer-size-max-width` | `1024px` | Cap on the centered content row; below it, the row simply follows the bar's width. |
| `--footer-space-inset` | `var(--spacing_inset-xs)` | Inner padding of the centered row. |

`kb-footer` paints no background of its own, so the page background shows
through — set `background-color` directly on the element when the bar needs
to read as a separate surface:

```css
/* A taller, wider, tinted footer */
kb-footer {
  --footer-size-height: 96px;
  --footer-size-max-width: 1280px;
  background-color: var(--color-master-lighter);
}
```

## States and accessibility

- `kb-footer` has no `hidden` attribute and no custom states — it doesn't
  use the `Hidden` mixin, so remove the element itself when the bar
  shouldn't be in the layout.
- The inner `<footer>` exposes a `contentinfo` landmark for the page. Use
  a single `kb-footer` per page; a second one splits that landmark and
  makes "jump to page footer" ambiguous for screen reader users.
- The element adds no focus management of its own (its shadow root is not
  `delegatesFocus`), so slotted links and buttons keep their own native
  focus order — keep them in the reading order you want, `leading` first.

## Do's and don'ts

| Do | Don't |
|---|---|
| Slot your own copyright line into `leading` | Ship the built-in fallback, which hardcodes a year, a name, and a language |
| Keep a single `kb-footer`, at the page root | Reuse it as the bottom bar of a card or dialog — its landmark belongs to the page |
| Wrap multiple links in a `<kb-stack direction="row">` inside a slot | Slot several elements side by side and expect the region to space them |
| Keep both sides to a single short line | Fill the bar with content that wraps — the 72px height is fixed |
