# Stack

A stack is a flex container with a token-based gap: it arranges whatever
is slotted into it in one row or one column, aligned and spaced by
attribute. It's a layout primitive with no surface of its own — no
background, no padding, no border — so it never looks like anything on its
own.

## When to use

- **Spacing a group of siblings consistently** — a row of buttons, a
  column of form fields, a toolbar — without writing a one-off flex rule
  for each group.
- **Anchoring content to opposite ends** — `justify="space-between"` on a
  row, the everyday "label on the left, action on the right".
- **Grouping content inside another component's slot**, where the parent
  gives you one region and you need several elements arranged in it.

## When not to use

- **A page header or footer bar** — `<kb-header>` and `<kb-footer>` are
  the landmark versions of the same centered-row idea, with a fixed height
  and a max width. A stack has neither and exposes no landmark.
- **A visible surface** — a grouping that needs a background, padding, or
  a border is a `<kb-card>`. A stack styles nothing but the layout of its
  children.
- **A two-dimensional grid** — this is a single flex line; children never
  wrap onto a second one. Use CSS Grid directly when rows *and* columns
  matter.
- **Spacing text inside a paragraph** — `<kb-text>` already carries its
  own type and rhythm; a stack around inline text just adds a flex
  context.

## Composition

- **Can contain**: anything. The shadow root is a single unnamed `<slot>`
  (see `component.js`), so every child renders in source order as a flex
  item — kuba elements and plain HTML alike.
- **Can be a child of**: anything, including another `kb-stack`. Nesting a
  column of rows is the normal way to build a two-dimensional layout out
  of this primitive, since a single stack never wraps.

Because the host is the flex container, children stretch or shrink by the
usual flex rules — a child with `flex: 1` fills the leftover space, which
is how you get "this one grows, the rest stay natural".

## Direction, alignment, and spacing

`direction` is the only attribute with a closed set of values (`row` or
`column`). `align` and `justify` are passed through to `align-items` and
`justify-content` verbatim, so any valid CSS value works — and an invalid
one silently does nothing.

The pair to keep straight:

| Attribute | Acts along | Common values |
|---|---|---|
| `justify` | the direction of the stack (main axis) | `flex-start`, `center`, `space-between`, `flex-end` |
| `align` | across it (cross axis) | `start`, `center`, `stretch`, `baseline` |

In a `row`, `align="center"` vertically centers items of different
heights; in a `column`, `align="stretch"` makes children fill the width.
Switching `direction` swaps which attribute does what — check both when a
stack changes orientation at a breakpoint.

`spacing` selects a step of the inset scale
(`packages/pixel/tokens/spacing.css`), which is what keeps the rhythm
between groups predictable across a page:

| `spacing` | Gap | Use for |
|---|---|---|
| `quarck` / `nano` | 4 / 8px | Elements that read as one unit — icon and its label, input and its helper. |
| `xs` | 16px | The default: siblings inside a group. |
| `sm` / `md` | 24 / 32px | Separating groups from each other inside a section. |
| `lg` and up | 40px+ | Section-level separation, where a `<kb-inset>` may serve better. |

## Styling

The gap is the one visual decision not fully expressed by an attribute,
so it's also exposed as a custom property — useful when the spacing has to
respond to a media query, which an attribute can't do.

| Custom property | Default | Controls |
|---|---|---|
| `--stack-space-gap` | `var(--spacing_inset-{spacing})` | Gap between children, overriding the `spacing` attribute. |

```css
/* Tighten the gap on narrow screens without re-rendering the attribute */
@media (width < 600px) {
  kb-stack.toolbar { --stack-space-gap: var(--spacing_inset-nano); }
}
```

Everything else (`align`, `direction`, `justify`, `height`, `width`) is
already an attribute and is applied directly to the host, so set those
rather than overriding the same properties in CSS.

## States and accessibility

- `kb-stack` uses the `Hidden` mixin: setting `hidden` adds a `hidden`
  custom state and `display: none` via `:host(:state(hidden))`, removing
  the stack and its children from the layout and the accessibility tree.
- It also carries `height` and `width` from the `Height`/`Width` mixins,
  applied straight to the host — use them instead of an external CSS rule
  when a stack needs a fixed size.
- The element renders no landmark, no role, and no label. It's a layout
  box: group semantics have to come from what you put inside it (a
  `<nav>`, a `<ul>`, a fieldset), or from ARIA on the host.
- Visual order follows source order, so keyboard order matches what's on
  screen. Don't reverse it with `flex-direction: row-reverse` from
  outside — that separates the two.

## Do's and don'ts

| Do | Don't |
|---|---|
| Pick a `spacing` step from the scale | Set a one-off pixel gap in CSS next to a scale that already fits |
| Nest stacks to build a two-dimensional layout | Expect children to wrap — a stack is a single flex line |
| Reach for `<kb-card>` when the group needs a surface | Add a background and padding to a stack to fake one |
| Keep source order equal to reading order | Reorder visually with `row-reverse` or `order` |
