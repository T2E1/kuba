# Textarea

A textarea is a multi-line text field that grows with what's typed into
it. It wraps a real `<textarea>` and reports value and validity to the
owning `<form>` through `ElementInternals`, so it submits like a native
control — with the manual resize handle removed, since the height is
managed for you.

## When to use

- **Free-form text longer than a line** — a bio, a note, a message, a
  description.
- **Content whose length varies a lot between users** — the field grows
  instead of forcing a scroll inside a fixed box.

## When not to use

- **A single-line value** — use `<kb-input>`. It carries the full set of
  constraint attributes (`type`, `pattern`, `min`/`max`) that a textarea
  doesn't.
- **Rich text** — this is plain text; there's no formatting, no markdown
  preview, no toolbar.
- **Very long documents** — a field that grows without bound pushes the
  submit action off screen. Past a few paragraphs, an editor view serves
  better than a growing field.

## Composition

- **Can contain**: content for its three named slots — `label`, `helper`
  and `validity` (see `component.js`). Anything unslotted is dropped.
  `<kb-label>`, `<kb-helper>` and `<kb-validity>` all assign themselves to
  the matching slot on connect, so nesting them is the whole setup — more
  than one `<kb-validity>` can share the slot.
- **Can be a child of**: a `<form>`, a `<kb-form>`'s template, or nothing
  — the element works standalone, it just has no form to submit to.

```html
<kb-textarea name="bio" required>
  <kb-label>Bio</kb-label>
  <kb-helper>A sentence or two about yourself.</kb-helper>
  <kb-validity state="valueMissing">
    Tell us something about yourself.
  </kb-validity>
</kb-textarea>
```

## Height and growth

The field starts at `--textarea-size-min-height` (128px, roughly four
lines) and grows on every input: the handler resets the height and
re-applies `scrollHeight` (see `textarea.ts`), so the box always fits its
content exactly.

Two consequences of that design:

- **It never shrinks below the minimum**, and it never scrolls —
  `overflow: hidden` with `resize: none` means the content is always fully
  visible. A long answer makes a long field.
- **The growth is inline style on the inner element**, applied per input
  event. Setting a `height` from outside is overwritten as soon as the
  user types; use `--textarea-size-min-height` to change the starting
  size.

Pick the minimum height to signal the expected answer length — a two-line
box invites a sentence, an eight-line box invites a paragraph.

## Validation

Constraints are declared as attributes and evaluated by the browser; the
outcome is mirrored onto the host as an `invalid` custom state.

- `required` is the constraint that applies here; the length and format
  constraints of `<kb-input>` are not forwarded by this element.
- Read the result through `checkValidity()`, `reportValidity()`,
  `validity` and `validationMessage`.
- While the host is `invalid`, the `helper` slot is hidden (see
  `style.js`), so the error message replaces the hint rather than stacking
  under it.

`reset()` clears the value and the invalid state and dispatches `reset`,
which is how `<kb-form>`'s reset reaches the field.

## Events

The element dispatches `changed` with the new value as `event.detail` on
every value change — the same event `<kb-input>` and `<kb-fileupload>`
publish, so an arc written for one field works for any of them:

```html
<kb-textarea name="note"></kb-textarea>
<kb-render>
  <kb-on value="note/changed:method/render"></kb-on>
  <template>{}</template>
</kb-render>
```

## Styling

The field's surface is exposed as `--textarea-*` custom properties, which
inherit through the shadow boundary — set them on the element (or any
ancestor) rather than reaching into its shadow DOM.

| Custom property | Default | Controls |
|---|---|---|
| `--textarea-color-background` | `var(--color-master-lightest)` | Field background. |
| `--textarea-color-background_disabled` | `var(--color-master-lighter)` | Background when disabled or read-only. |
| `--textarea-color-border` | `var(--color-master-light)` | Border in the resting state. |
| `--textarea-color-focus` | `var(--color-primary)` | Border on focus. |
| `--textarea-color-invalid` | `var(--color-danger)` | Border while the `invalid` state is set. |
| `--textarea-color-text` | `var(--color-master-darkest)` | Typed text. |
| `--textarea-color-text_disabled` | `var(--color-master)` | Text when disabled or read-only. |
| `--textarea-color-placeholder` | `var(--color-master)` | Placeholder text. |
| `--textarea-font-family` | `var(--font-family-base)` | Type family. |
| `--textarea-font-size` | `var(--font-size-xxs)` (14px) | Type size. |
| `--textarea-line-height` | `var(--line-height-lg)` | Line height — the main lever on how many lines fit the starting height. |
| `--textarea-size-min-height` | `128px` | Starting height, before the field grows. |
| `--textarea-space-inset` | `var(--spacing_inset-nano) var(--spacing_inset-xs)` | Field padding — accepts the full CSS shorthand. |
| `--textarea-border-radius` | `var(--border-radius-sm)` | Corner rounding. |
| `--textarea-space-gap` | `var(--spacing-nano)` | Gap between label, field, and helper/validity. |

Width is an attribute (`width`, from the `Width` mixin), not a custom
property — set it there rather than in CSS.

```css
/* A shorter box, for a one-sentence answer */
kb-textarea.brief {
  --textarea-size-min-height: 72px;
}
```

## States and accessibility

- The element uses the `Hidden` mixin: `hidden` adds the `hidden` custom
  state and `display: none`, removing the field from layout and from the
  accessibility tree.
- `invalid` is a custom state derived from the Constraint Validation API,
  not an attribute you set.
- The inner `<label for>` targets the inner textarea via `id` (falling
  back to `name`), so slotted label content associates properly — but only
  when one of them is set.
- Growing the field moves everything below it down. Keep the submit action
  in a position that survives that (inside `<kb-form>`, after the fields),
  so it doesn't jump away while the user types.
- `disabled` removes the field from submission; `readonly` keeps its value
  in the `FormData`.

## Do's and don'ts

| Do | Don't |
|---|---|
| Size `--textarea-size-min-height` to the expected answer | Ship the default 128px for a field that always holds one line |
| Set `name` (or `id`) so the label associates and the value submits | Rely on a visible `<kb-label>` alone to name the field |
| Use `<kb-input>` when the answer is a single line | Reach for a textarea because it "looks roomier" |
| Debounce `changed` before driving a request | Fire a request per keystroke straight from the event |
