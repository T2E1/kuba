# Icons

`<kb-icon>` (`packages/component/icon`) renders a glyph from the
**Material Symbols Rounded** set via a font ligature — not inline SVG, not
a sprite sheet. That keeps the package lightweight: adding a new icon is a
matter of writing the right `use`, not importing an asset.

```html
<kb-icon use="home" size="md" color="primary"></kb-icon>
```

| Attribute | What it does |
|---|---|
| `use` | The Material Symbols ligature name to render, e.g. `"home"`, `"search"`, `"favorite"`. |
| `size` | Size keyword, resolved against `--font-size-{value}` — the same typographic scale as **Guidelines/Design Tokens/Typography**. |
| `color` | Icon color, resolved against `--color-{value}`. Without the attribute, it falls back to `currentColor` — the icon inherits the color of the surrounding text. |

## Size follows the typographic scale

Icons don't have a size scale of their own — they use `--font-size-xxxs`
through `--font-size-giant`, the same tokens as **Guidelines/Design
Tokens/Typography**. This guarantees that an icon next to text
(`size="sm"` alongside a `<kb-text size="sm">`, for example) always aligns
visually with no manual tweaking.

## Style types per brand

Because `<kb-icon>` resolves size and color through Design Tokens,
swapping a brand's token sheet (**Guidelines/Themes**) is already enough
to change the look of every icon in the product — no new prop, no
component variant.

## Libraries

We chose Material Symbols over drawing a set from scratch: it's free,
maintained by Google, covers most of a digital product's use cases, and is
served as a font, which removes the need to manage individual SVG files.
If a specific icon isn't in the set, the path is to evaluate a
complementary library before drawing a custom glyph from scratch.
