# Themes

We're at the initial version of Kuba's brand tokens. Today there's a
single `Design Tokens` sheet (`packages/pixel/tokens/`), but the structure
is already designed to support multiple brands and themes without touching
a single component — just by swapping which token sheet is active.

## How switching brands works

Every element consumes color, typography, and spacing exclusively through
`var(--token-name)` — never a hardcoded value inside `style.js`. That
means creating a new brand is, in principle, a matter of replacing
`packages/pixel/tokens/color.css` (and, if the brand also has a different
typographic voice, `fontFamily.css`) with an equivalent sheet using the
same variable names and different values — no component needs to know the
brand changed.

## Multiple themes per brand

The same principle applies to seasonal variations or per-user-profile
looks within a brand: swapping only the color variables is enough for a
campaign (Black Friday, say) or a tier distinction (silver, gold) without
duplicating Elements or Blocks.

## Light and dark mode

Every color token in `color.css` is already declared with `light-dark()`,
the native CSS light/dark pair:

```css
--color-primary: light-dark(#6d5cae, #7a5ed1);
```

The first value is used under `color-scheme: light`; the second under
`color-scheme: dark`. Today `packages/pixel/reset/body.css` pins
`color-scheme: light` — dark mode is already encoded in every token, but
isn't yet exposed as a toggle a Kuba consumer can flip.

When it is switched on, the plan isn't to create a second sheet of brand
tokens: it's simply to flip how the neutral scale is applied — everything
that's "high" today (our neutral scale of light tones) becomes "low" (our
neutral scale of dark tones) and vice versa, via `color-scheme` on the
root element.
